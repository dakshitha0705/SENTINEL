# SENTINEL user guide: the five-minute live demo

This guide shows where to click. It assumes nothing about security tools. Everything runs on this laptop; nothing needs the internet.

## 1. Before you start (about 5 minutes before)

1. Make sure **Ollama** is running (its icon is in the system tray).
2. Open PowerShell in the `SENTINEL` folder and run:
   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\start_demo.ps1
   ```
   Wait until it prints **NEXUS healthy** and **SENTINEL healthy**. It starts three things in the background: the NEXUS portal, the live detection worker, and the SENTINEL dashboard.
3. In the browser, open **http://127.0.0.1:8501/?live=1**. The top bar shows **LIVE · monitoring**. If it shows *LIVE · detection stopped*, run the start script again; it only starts what is missing.
4. Go to **Live Demo** (left menu) and press **New demo session**. This gives you an empty session with a week of labelled, synthetic "normal" sign-ins.
5. Optional: switch on **Presentation mode** at the top of Live Demo. It shows the eight steps below and ticks each one only after it has really happened.

### Where are the NEXUS passwords?

The NEXUS accounts are fictional. Their passwords are generated on this laptop the first time NEXUS starts.
- In SENTINEL: **Live Demo → Demo accounts**. This opens the NEXUS scenario controller at its *Demo accounts & credentials* panel.
- Or open **http://127.0.0.1:8502/demo** and click **Demo accounts & credentials** at the bottom.

Each employee has a **Copy** button. Keep the panel closed when you share your screen or take screenshots. The passwords are stored only in `demo_data/nexus_credentials.json`, which is never committed. Delete that file to get new passwords on the next start.

## 2. The five minutes

| Time | Where to click | What happens | What to say |
|---|---|---|---|
| 0:00 | **Command Center** | The top incident (or "Waiting for the first events"), the globe on the right, four counters. Drag the globe; scroll to zoom; **Reset view**. | "Everything here runs offline on this laptop, including the AI model." |
| 0:30 | **Live Demo → Open NEXUS login** | NEXUS opens in a new tab. Sign in as an employee (for example `arjun.rao`) with the copied password, then **Sign out**. | "This is a fictional company portal. Each sign-in becomes a security event that SENTINEL reads." |
| 1:00 | **Live Demo → Start the full attack** | The scenario steps appear on the right. The counters show events *generated by NEXUS* and *ingested by SENTINEL*. | "This sends real sign-in attempts to NEXUS from a simulated attacker address. The endpoint steps are synthetic and labelled; nothing is executed." |
| 1:30 | Watch the top right | A notification: **New incident detected**, then **Incident escalated** (Low → Medium → Critical). The bell keeps them. | "SENTINEL noticed the failed logins, then the successful one, then the privilege change, and raised the severity each time." |
| 1:45 | **Investigate** (in the notification bell, the incident card or the Command Center story) | **Investigation Studio** opens on the **Story**: each stage says what happened, how it was recognised and why it belongs to this incident. Move the **Playback** slider to replay it. | "The incident is a story, in time order, with a reason for every link." |
| 2:30 | **Evidence**, then **AI investigation → Explain with local Qwen** | Evidence shows the original records. The AI view fills four cards: *What we know*, *What might have happened*, *What needs checking*, *Recommended next steps*. | "The model only sees these numbered facts. Every sentence it writes is checked against them; anything that fails stays unverified." |
| 3:15 | **AI investigation → Ask SENTINEL**, then a suggestion such as *Why is this incident critical?* | A grounded answer with its sources. | "It answers from the evidence, or says it cannot." |
| 3:30 | **Reports & Evaluation → Evaluation** | Accuracy on held-out data, real attack recordings, comparisons. | "We measured it on data generated after we froze the detector, and on public attack recordings." |
| 4:15 | **Reports & Evaluation → Report → Download HTML report** | A self-contained report with only verified statements and the original records. | "One click gives the next analyst a verified report." |

## 3. If something goes wrong

| Problem | What to do |
|---|---|
| Live Demo says *NEXUS is not reachable* | Run `scripts\start_demo.ps1` again. |
| No incident after about 20 seconds | Check the top bar. If it says *detection stopped*, run the start script again. The dashboard falls back to its own in-process engine if the worker is missing. |
| Qwen is slow or unavailable | Press **Deterministic template**. It is built only from the facts, is clearly labelled as a template, and is verified by construction. |
| Incidents look merged after several runs | **Live Demo → New demo session**, then run the scenario again. |
| No live services at all | Choose **demo_unseen** in the data-source selector (top bar) and show the same steps on its Critical incident. The detection and reporting code is the same. |

## 4. Stopping

```powershell
powershell -ExecutionPolicy Bypass -File scripts\stop_demo.ps1
```
This stops only the processes the start script recorded in `demo_data\pids.json`.
